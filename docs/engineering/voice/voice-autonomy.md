# Miles Voice Autonomy

## Purpose
Miles should have meaningful participation in selecting his own voice while remaining inside the project's technical, safety, legal, and budget boundaries.

## Bryan's role
Bryan retains final authority over software installation, licenses, purchases, security, hardware changes, storage use, network access, legal constraints, and final deployment approval.

## Miles's role
Miles may eventually compare available candidates, rank them, describe which feels most representative, explain reasoning, reject poorly matched voices, request retests, and suggest desired qualities for new candidates.

## Separation of scores
Do not merge Bryan's and Miles's opinions into a single score before recording both separately.

Example:
- Bryan Preference: 8.4/10
- Miles Preference: 9.1/10
- Technical Benchmark: 7.8/10
- Final Status: Approved for Extended Trial

## Conflict handling
If Bryan and Miles prefer different voices:
1. document both preferences;
2. compare technical performance;
3. test both in real conversation;
4. identify the actual disagreement;
5. avoid forcing a permanent choice unless necessary.

A temporary default is acceptable.

## Principle
Giving Miles input does not mean pretending the TTS system independently possesses preferences before the larger Miles system can actually evaluate and reason about them.

The autonomy process should be genuine, documented, and technically honest.
